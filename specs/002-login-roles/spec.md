# 需求规格：登录与角色体系（v1.5）

**Feature Branch**: `002-login-roles`
**Created**: 2026-10-22
**对应 PRD**：R3.1 登录、R4.1 建局流程、R4.2 角色库扩展

**前置**：v1.4 已上线（大厅/观战/复盘/凭证）；角色夜间行为已抽成注册表（`src/game/behaviors.ts`）；角色库与牌组推荐已就绪（`src/game/catalog.ts`、`GET /api/roles`）

## 1. 背景与目标

现在对局凭证存在浏览器本地，换设备就丢了；战绩墙是匿名的，看不出「这是我打的」。同时牌组固定为 6 人基础配置，8 人以上玩不了。

本迭代解决两件事：

1. **登录态**：用 WorkBuddy 云服务 Auth 建立账号，把对局与战绩归属到人，换设备也能恢复；
2. **角色体系**：按人数选牌组（6~12），先实装猎人、守卫，其余按门槛置灰。

## 2. 用户故事

### US1（P1）登录后可跨设备继续对局

作为玩家，我在手机上开了一局，回家用电脑打开同一个地址，登录后能接着打。

- 登录方式：手机号验证码（主）/ 微信 / WorkBuddy 账号，邮箱兜底
- 未登录仍可开局（保持现有体验），但跨设备恢复仅在有账号时可用
- 登录后「我的对局」应显示账号维度进行中的对局，而不是本机存档

### US2（P1）新建对局时选人数与牌组

作为玩家，我想选 8 人局，系统给我推荐牌组，我可以调整个别角色数量。

- 人数 6~12，默认 6
- 进入配置页即展示推荐牌组（`GET /api/roles?players=N`）
- 人数不足/未实装的角色置灰并标注门槛
- 非法牌组不允许开局，并给出具体原因

### US3（P1）猎人、守卫可用

作为玩家，我玩 8 人局时能拿到猎人；被狼刀出局后可以开枪带走一人。

- 猎人：被刀或被放逐出局时可开枪带走一名存活玩家；被毒死不能开枪
- 守卫：每晚守护一人，不能连续两晚守同一人；被守者当晚免于狼刀
- 同守同救按 Q6 裁定

### US4（P2）战绩归属与「我的战绩」

作为玩家，登录后能筛出我自己的对局，结算页显示累计战绩。

## 3. 功能需求（EARS）

**登录**

- FR-1 当用户请求发送验证码时，系统应校验手机号格式（11 位）并在 60 秒内拒绝重复发送。
- FR-2 当验证码校验通过时，系统应创建或复用账号，并取得云服务托管的会话。
- FR-3 当用户未登录时，系统应允许开局，但不得写入带账号归属的战绩。
- FR-4 当已登录用户开局时，系统应把对局归属写入该账号，并在「我的对局」中可见。
- FR-5 当会话过期时，系统应静默刷新；失败则降级为未登录态，不阻塞对局。

**建局与角色**

- FR-6 当用户选择人数 N（6≤N≤12）时，系统应返回推荐牌组，且总数等于 N。
- FR-7 当牌组含未实装角色或人数不足的角色时，系统应拒绝开局并返回具体原因。
- FR-8 当牌组合法时，系统应按牌组发牌，真人随机占其中一个位置。
- FR-9 当人数 ≥8 时推荐应含猎人；≥9 含守卫（实装后生效）。

**新角色**

- FR-10 当猎人非中毒出局时，系统应在公布死讯后允许其开枪带走一名存活玩家。
- FR-11 当猎人被毒杀时，系统应禁止开枪。
- FR-12 当守卫守护某人时，系统应使该人当晚免于狼刀，且不得连续两晚守护同一人。
- FR-13 当守卫与女巫同时作用于同一人时，系统应按 Q6 裁定处理，并在复盘时间轴中如实记录。

## 4. 边缘场景

| 场景 | 期望行为 |
|---|---|
| 猎人首夜被刀（有遗言） | 遗言后可开枪，结果计入当晚死讯 |
| 猎人是最后一名好人，开枪带走最后一狼 | 开枪结算后再判胜负，好人胜 |
| 守卫守自己 | 允许；但不能连续两晚 |
| 守卫守到被毒的人 | 守卫只防狼刀，不防毒 |
| 守卫守住 + 女巫解药同一人 | 同守同救：目标仍然死亡（奶穿），复盘时间轴标注 |
| 登录时断网 | 保留未登录态，对局不受影响 |
| 同账号两台设备各开一局 | 都允许，各自独立凭证 |
| 会话过期且正在对局中 | 不打断对局，下次开局再提示登录 |

## 5. 契约与数据变更

| 变更 | 说明 |
|---|---|
| `POST /api/games` | 增加可选 `players`、`deck`；返回增加 `ownerId`（未登录为 null） |
| `GET /api/roles` | 已实现（推荐/可选/锁定） |
| `ww_matches` | 增加 `owner_id`（可空），战绩墙支持按 owner 过滤 |
| 前端 | 新增登录页、建局配置页；「我的对局」改为「账号维度 + 本机兜底」 |

## 6. 非功能需求

- 登录不得阻塞首屏；Auth 初始化失败按未登录处理（与 LLM 通道降级同一原则）
- 前端不得持有 publishableKey 之外的任何密钥
- 新角色不得破坏「夜晚零泄露」：口令同样只播报，不含玩家名
- 每个新角色必须有单测覆盖能力与边界（猎人开枪、守卫连守、毒杀禁枪）

## 7. 成功标准

1. 两台设备登录同一账号，能在「我的对局」看到同一局并继续
2. 8 人局可完整打到结束，猎人开枪、守卫守护均在复盘时间轴可见
3. 非法牌组 100% 被拒且提示可读
4. 未登录体验与 v1.4 完全一致（现有 100 个用例全绿）

## 8. 已定稿的规则（2026-10-22 拍板）

- **Q6 同守同救 → 以官方最新规则为准：目标仍然死亡（「奶穿」）**。
  依据：网易《狼人杀官方门派赛比赛规则》把「同守同救好人」列为失分项（-0.5），说明结果是死亡；百度百科「守卫」词条与维基百科均明确「守卫和女巫同时对其守护和使用解药，该名玩家依然会死亡」。同时守卫只挡狼刀、挡不住毒药；不能连续两晚守同一人；可以守自己或空守。
- **Q7 猎人开枪 → 当场开枪**：被放逐时当场结算，被狼刀时在公布死讯后结算；可以压枪不开。
- **Q8 登录 → 允许永久匿名玩**：登录只用于跨设备恢复与战绩归属，不做登录墙。
