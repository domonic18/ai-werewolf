# AI 狼人杀 · 产品需求文档（PRD）

> 最后更新：2026-10-23 ｜ 对应线上版本：v1.9.2
> 背景：项目始于 WorkBuddy 1024 造物挑战（截止 2026-11-01），定位为**生产级网页游戏**，长期运营于个人站点生态（17aitech.com）。
> 本文是产品与范围的唯一事实来源；视觉规范见 [standard/DESIGN-V2.md](standard/DESIGN-V2.md)，安全见 [standard/SECURITY.md](standard/SECURITY.md)，AI 行为见 [AI-PERSONA.md](AI-PERSONA.md)。

## 一、产品定位

- **一句话**：一个人也能玩的狼人杀——AI Agent 补位，全程大模型驱动言行；未来支持真人多人。
- **双目标**：短期冲参赛评审（完成度 + AI 创新性），长期作为个人站点的流量型产品。
- **平台**：Web（移动优先），WorkBuddy Cloud Service 提供后端（LLM / 数据库 / 认证）。

## 二、需求细化

### R1 生产级整体体验（总纲）

| 维度 | 起点 | 现在 |
|---|---|---|
| 视觉 | 单页三屏，风格统一但简单 | 六屏品牌化视觉体系（docs/standard/DESIGN-V2.md）：色板 / 字体 / 图标 / 图像 / 动效 / 夜幕过场 |

| 数据 | 战绩墙 | 个人战绩（账号维度）、观战时间轴；对局回放列入 v2.0 |

### R3 登录与游戏大厅

**3.1 登录（v1.5 已上线）**
- WorkBuddy 云服务 Auth 支持四种方式，SDK 为 `@tencent-ai/workbuddy-cloud-sdk` 的 `cloud.auth`；**本产品提供其中三种**：
  1. **手机号短信验证码**（`sendOtp({phone})` + `verifyOtp`）—— 默认主推，中国大陆 11 位校验，60s 重发倒计时
  2. **微信登录**（`signInWithOAuth({provider:'wechat'})`）
  3. **使用 WorkBuddy 登录**（`signInWithOAuth({provider:'workbuddy'})`，PKCE + Relay，仅 Web）
- **邮箱通道不提供**：SDK 支持 `{email}`，但未在线上验证过，产品上不放入口（`WB_AUTH_PROVIDERS` 默认 `phone,wechat,workbuddy`）。
  三种方式均已在线上跑通（2026-10-22 人工验证）。
- 发送验证码只认 `credentials.phone / credentials.email`；按 SDK 类型注释传 `phone_number` 会在运行时直接报错（见 AGENTS.md 硬性禁止）
- 无游客模式：SDK 不提供匿名登录，禁止 localStorage 假会话；对局归属账号，登录是可选增强而非登录墙
- 无密码体系：验证码注册/登录均不设密码
- 部署约束：OAuth 的 `redirectTo` 必须是已发布的 HTTPS 站点根路径，回调需在路由守卫前按 `provider` 分发
- **Provider 未开就不显示**：登录页按 `/api/auth-config.providers` 渲染入口（部署方用 `WB_AUTH_PROVIDERS` 声明），避免「点了必失败」的按钮
- **遗留**：微信 / WorkBuddy 两条 OAuth 仍需在线上人工跑通一次（云服务后台开启 Provider 后验证）

**3.3 我的战绩（v1.9.5 已上线）**
- 入口：首页账号条「我的战绩」、结算页「全部战绩」；地址 `#me`
- 内容：累计战绩（总对局 / 胜场 / 胜率）、进行中的对局（可继续）、最近每一局的角色与胜负
- 口径：只统计自己坐庄打完的局；中止的局单列数量、不计入胜率。胜负按**自己那一局的身份**判
  （狼阵营赢 = 我是狼），表里 `player_role` 存中文名，`wolf` / `黑狼王` 都要认
- 未登录：说明 + 去登录；登录态失效（服务端认不出人）单独提示，避免 0 局被误读成「没打过」

**3.2 游戏大厅（v1.4 已上线）**
- 展示：进行中对局（房主、人数、当前阶段、轮次、观战人数），统计卡 + 筛选（全部/真人局/决赛圈/我的）+ 排序（热度/开局时间）+ 游标分页 + 密度自适应
- 操作：观战、快捷开局、回到自己那一局（带凭证）
- 观战红线：观战者看得到全量身份（上帝视角），但**写操作一律拒绝**（`/action`、`/quit` 需 `X-Player-Token`）；玩家侧快照不含他人身份
- **Q3 已关闭**：观战不延迟。上帝视角是卖点，延迟反而让「看朋友打」变难

### R4 新建游戏与角色体系

**4.1 建局流程（v1.5 已上线）**：首页「开始一局」→ 配置页（人数/角色）→ 开局
- 人数：6~12 人；真人为 1，其余 AI 补位（真人多人见 R7）
- 角色配置：从角色库挑选 + 数量；系统按人数给推荐牌组（一键模板）
- 校验规则：神职数 < 半数；狼人 ≥2 且 < 半数；人数不满足的角色置灰
- 保留一条「快速开始 · 默认 6 人标准局」直达路径（省事的用户不必过配置页）

**4.2 角色库**（按人数门槛）

| 角色 | 阵营 | 门槛 | 能力 | 状态 |
|---|---|---|---|---|
| 狼人 | 狼 | ≥6 | 夜晚刀人 | ✅ |
| 村民 | 好 | ≥6 | 无技能 | ✅ |
| 预言家 | 好 | ≥6 | 夜晚验人 | ✅ |
| 女巫 | 好 | ≥6 | 解药/毒药各一 | ✅ |
| 猎人 | 好 | ≥8 | 出局开枪（被毒除外） | ✅ |
| 守卫 | 好 | ≥8 | 每晚守护一人（不能连守） | ✅ |
| 白痴 | 好 | ≥9 | 首次被放逐翻牌免死，此后失去投票权 | ✅ v1.8 |
| 长老 | 好 | ≥10 | 首次被狼刀不死；被毒/枪/放逐后好人神职技能失效 | ✅ v1.8 |
| 黑狼王 | 狼 | ≥10 | 出局开枪（被毒除外） | ✅ v1.8 |
| 摄梦人 | 好 | ≥12 | 每晚标记一人，被标者不能被刀 | 未实装 |

- 推荐牌组按人数**显式配方**，不再「神职不够拿平民补」：9 人起有白痴，10 人起有黑狼王，12 人起有长老
- **Q4 已关闭**：v1.5 上猎人 + 守卫，v1.8 上白痴 + 长老 + 黑狼王；摄梦人留到 v1.10

**4.3 AI 人格与推理差异化（v1.7 已上线）**

- **信息边界**：AI 只知道自己的身份与技能状态；狼人额外知道队友。别人的身份只有被放逐翻牌才公开，夜晚死亡不翻牌。
  AI 视图与观战上帝视角是两个函数，禁止合并。
- **人格参数**：每人 `skill / style / talk / push / suggestibility` + 每局随机 `mood`，牌感与状态都会抖动
- **差异落到机制**：记忆窗口 8~24 条发言、可推理深度、发言字数 15~120、采样温度 0.6~1.1
- **角色池**：12 位 AI，牌感 0.28（大熊）~0.85（阿岚）
- 详见 [AI-PERSONA.md](AI-PERSONA.md)

### R5 对局生命周期与断线恢复（✅ v1.3 起）

**状态机**：`创建 → 进行中（night/day/vote 循环）→ 结束（正常结算 / 异常中止）`
- 权威状态在服务端，客户端只存对局 ID
- 刷新/误关恢复：对局 ID 存 localStorage，重进首页出现「继续」横幅；重新拉全量事件流
- 房间保留：已结束 2 小时；进行中但 **30 分钟无操作判弃局**（回收前先停引擎，避免 AI 空转烧额度）
- 主动退出 = 明确结束（弹确认）；对局结束/中止自动清理本地记录

### R8 传播与邀请（v1.11）

目标：让「一局打完」有东西可发，让「谁邀请谁」留得下来——传播攒量，邀请攒人。

> 设计稿：Ardot 文件 `739278326396024` → 页面「v1.11 邀请与分享」（6 屏，390×844，可直接量取）。
> 仓库不留原型 HTML，设计只认 Ardot 这一份。

**8.1 邀请关系**

- 分享链接带 `?ref=<邀请码>`；邀请码是登录后生成的短码（大写字母 + 数字，无歧义字符），一个账号一个、稳定不变
- 落地页（首页）顶部出现邀请横幅：「X 邀请你来打一局」+ 对方的局数与胜率 + 「入席开局 / 先看看」
- 绑定时机：被邀请人**登录后**写一条邀请关系；同一对只记一次，自己不能邀请自己
- 未登录仍可开局（匿名局照旧），但**不建立**邀请关系——落地页要说清这一点

**8.2 好友列表与战绩（`#me`）**

- 新增「我邀请的朋友」区块：头像、昵称、共几局、胜率、最近一局时间，按最近活跃排序
- 只展示**聚合**（局数 / 胜率），不展示对方每局明细；对方可在设置里 `hide_stats`，隐藏后只显示「在玩」
- 空态必须给出路：说明 + 「复制邀请链接」，不做死胡同

**8.3 分享（按性价比排序）**

| 能力 | 说明 | 位置 |
|---|---|---|
| 战绩卡出图 | 客户端 canvas 画 3:4.6 竖版图：判定 + 我的身份 + 一句我自己的话 + 关键回合 + 二维码；长按保存 / 系统分享 | 结算页 |
| 分享面板 | `navigator.share` 优先，不支持则复制链接；含「复制链接 / 二维码」两项 | 结算页、局中观战入口 |
| 观战链接 | 复用既有 `#watch=<gameId>` 深链，观众不占座、不消耗模型调用 | 局中、大厅 |
| 标题与 og | `<title>` 动态化（第 N 夜 / 决赛圈）+ `og:title/og:description/og:image` | 全站 |

- 分享图在**客户端生成**，不上传服务器（省存储也省隐私风险）
- 邀请码与二维码指向同一入口，扫码进来即带 `ref`

**8.4 明确不做（附原因，避免反复讨论）**

| 不做 | 原因 |
|---|---|
| 微信好友关系链 | 开放平台不提供好友列表接口；小程序的 `wx.getFriendCloudStorage` 只能拿「也玩过同一小游戏」的好友，且只能跑在开放数据域、主域只拿到 canvas 图像。个人号相关接口全是外挂协议，封号风险 |
| 微信自定义分享卡片 | 需已认证公众号 + 站点根目录放校验文件；当前域名由平台托管，放不了 |
| 「分享得奖励 / 邀请送 X」 | 微信对诱导分享有明确处罚 |
| 好友排行榜 | 用户量小时空榜比没有更伤；等真人房上线、有稳定回流再做 |
| 发言辅助（提示 / 脚手架 / AI 起草） | 与本产品定位不符（评估后决定不做），保留原快捷语与自由输入 |

**8.5 数据表**

```sql
ww_profiles (user_id text primary key, nickname text, avatar_url text,
             invite_code text unique, hide_stats boolean default false, created_at timestamptz)
-- invitee_id 做主键：一个新人只归属于第一个邀请他的人（8.6 决策 2）
ww_invites  (invitee_id text primary key, inviter_id text not null, created_at timestamptz)
```

非功能要求：邀请与好友接口必须要求登录；只回本人可见的聚合数据；不做跨账号的明细查询。

**8.6 已定决策（2026-10-23 澄清）**

| # | 问题 | 结论 |
|---|---|---|
| 1 | 好友列表用什么名字/头像 | 账号昵称 + 头像；手机号登录拿不到昵称时，首次进「我的战绩」请用户填一次（写入 `ww_profiles`）。头像先做首字色块 |
| 2 | 一个新人被多人邀请 | 只记第一条（`invitee_id` 唯一），后续邀请忽略；语义清晰、天然防刷 |
| 3 | 战绩卡那句「自己的话」 | **系统生成**（从当局复盘里抽真实片段），不打断玩家输入 |
| 4 | 分享入口 | 结算页 + 局中「叫朋友来看」+ 我的战绩页「邀请朋友」，首页不加 |
| 5 | 参赛前范围 | 战绩卡 + 分享 + 邀请全链路 + og/二维码收尾 |
| 6 | 好友战绩默认可见性 | 默认公开聚合（局数 + 胜率），对方可在「我的战绩」关闭 |
| 8 | 是否显示「谁邀请了我」 | 不显示 |
| 9 | 长期不活跃的邀请好友 | 不静默删除：保留、排最后、标「很久没来」 |

**8.7 实现细节（默认值，已确认）**

- 好友列表最多 20 人，按最近活跃排序；未打完一局的人显示但胜率位为「—」并置灰
- 未登录点邀请链接：先玩，登录后补记关系（同一浏览器 24h 内**最后一次**点击的 `ref` 生效）
- 分享降级：`navigator.share` → 复制链接 → 二维码；微信内置浏览器不支持 `navigator.share`，落到「复制链接 + 提示右上角」
- 战绩卡二维码指向**站点首页（带 ref）**，不指向观战链接（房间 2 小时回收会变死链）
- 观战分享沿用 `#watch=<gameId>`，提示「对局结束后 2 小时内可看」
- 埋点只记 4 个事件：`share_click` / `landing` / `login` / `invite_bound`；不引第三方。
  落在 `ww_events`（服务端 `EventStore`），身份存**加盐哈希**而非账号 id（表对 anon 可读，不能存原值）；
  `POST /api/track` 有事件名白名单，`GET /api/track/summary` 需登录且只回聚合
- `hide_stats` 开关放「我的战绩」页的邀请面板内（账号卡下方），不新开设置页；
  关闭后**服务端不再返回局数与胜率**，前端拿不到数字，也就无从遮挡

**8.8 验收标准**

1. 对局结束页能生成一张 1080×1656 的战绩卡（判定、身份、系统生成的复盘句、回合数、同行玩家、二维码），可保存为 PNG；卡上不出现任何本局未公开信息（只含已结算数据）。
2. 三个位置都能唤起分享：结算页、局中（观战链接）、我的战绩页（邀请链接）；`navigator.share` 不可用时降级为复制链接并给出明确提示。
3. 带 `?ref=` 打开首页出现邀请横幅（邀请人代号 + 局数 + 胜率）；未登录可正常开局，登录后关系写入 `ww_invites`；同一 `invitee` 只保留第一条；自己邀请自己被拒绝。
4. 「我的战绩」页显示「我邀请的朋友」：昵称、局数、胜率、最近活跃；0 局者显示「—」；超过 180 天未活跃标「很久没来」并排最后；上限 20 人。
5. `hide_stats` 关闭后，邀请人的列表里该好友只显示「在玩」，不显示胜率。
6. 页面 `<title>` 随场景变化（大厅 / 第 N 夜 / 结算），并带 `og:title / og:description / og:image`。
7. 接口层：邀请与好友接口未登录返回 401；不返回任何跨账号明细；`ww_invites` 写入幂等。
8. 全量 `npm test` 通过，新增用例覆盖：邀请幂等与自邀请拦截、好友列表聚合口径、战绩卡数据裁剪（不含他人身份）。

## 三、非功能需求

- **性能**：单局 LLM 调用 20~40 次；响应 P95 < 8s；轮询 1.2s/次（观战 1.6s）
- **安全**：服务端权威状态；观战零信息泄露；开源仓库零密钥；限流与输入边界见 [standard/SECURITY.md](standard/SECURITY.md)
- **成本**：模型可切换（首选 flash 级）；单人 10 分钟最多 3 局，全站每分钟 10 局
- **可观测**：对局事件全量留存（客户端保留最近 500 条），便于复盘与排障
