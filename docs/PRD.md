# AI 狼人杀 · 产品需求文档（PRD）

> 版本：v1.4 已实现 ｜ 状态：Q2 已定稿；Q3/Q4/Q5 待确认（不影响 v1.4 交付）
> 背景：项目始于 WorkBuddy 1024 造物挑战（截止 2026-11-01），定位升级为**生产级网页游戏应用**，长期运营于个人站点生态（17aitech.com）。

## 一、产品定位

- **一句话**：一个人也能玩的狼人杀——AI Agent 补位，全程大模型驱动言行；未来支持真人多人。
- **双目标**：短期冲参赛评审（完成度 + AI 创新性），长期作为个人站点的流量型产品。
- **平台**：Web（移动优先），WorkBuddy Cloud Service 提供后端（LLM / 数据库 / 认证）。

### R3 登录与游戏大厅

**3.1 登录（v1.5）**
- **已核实**（2026-10-22，WorkBuddy 云服务 Auth 能力边界）：Web 应用支持四种方式，SDK 均为 `@tencent-ai/workbuddy-cloud-sdk` 的 `cloud.auth` 能力：
  1. **手机号短信验证码**（`sendOtp({phone})` + `verifyOtp`）—— 默认主推，中国大陆 11 位校验，60s 重发倒计时
  2. **邮箱验证码**（同上，`{email}`）—— Tab 备选
  3. **微信登录**（`signInWithOAuth({provider:'wechat'})`，一键授权/扫码同一流程）
  4. **使用 WorkBuddy 登录**（`signInWithOAuth({provider:'workbuddy'})`，PKCE + Relay，仅 Web）
- **已定**（Q2 关闭）：主推手机号验证码；邮箱、微信、WorkBuddy 三者并列为次要入口。按钮文案必须用「使用 WorkBuddy 登录」
- **无游客模式**：SDK 明确不提供匿名登录，且禁止 localStorage 假会话——对局数据归属账号，登录是前置条件（原型 05 已按此修订）
- 无密码体系：验证码注册/登录均不设密码；如未来需要密码，须显式走 `verifyOtp(password)` / `signInWithPassword`
- 部署约束：微信 / WorkBuddy 两种 OAuth 的 `redirectTo` 必须是**已发布 HTTPS 域名的站点根路径**（localhost / 预览地址会被 Relay 拒绝），回调需在路由守卫前用 `handleWorkBuddyCallback` / `handleWechatWebCallback` 按 `provider` 参数分发，成功后清除 `code/state/provider`
- 前置开关：微信、WorkBuddy Provider 需在 WorkBuddy 云服务管理页为应用开启（应用代码无法代开）

**3.2 游戏大厅（v1.4 · 已实现）**
- 展示：进行中对局列表（房主、人数、当前阶段、第几轮、观战人数），统计卡 + 筛选（全部/真人局/决赛圈/我的对局）+ 排序（热度/开局时间）+ 游标分页 + 密度自适应（≥6 局切紧凑行）
- 操作：观战（上帝视角投影 `/spectate`）、快捷开局、从大厅回到自己那一局（带凭证）
- 观战红线：观战者看得到全量身份（上帝视角），但**写操作一律拒绝**（`/action`、`/quit` 需 `X-Player-Token`）；玩家侧快照仍不含他人身份
- **开放问题 Q3**：观战是否需要延迟 N 秒？当前实现为**不延迟**，代码预留 `visibleAt` 未启用

### R4 新建游戏与角色体系（v1.5）

**4.1 建局流程**：首页「新建游戏」→ 配置页（人数/角色）→ 开局
- 人数：6~12 人；真人为 1，其余 AI 补位（真人多人见 R7）
- 角色配置：从角色库挑选 + 数量；**系统按人数给推荐配置**（一键模板）
- 校验规则：神职数量 < 玩家半数；狼人数随总人数推荐（6 人 2 狼 … 12 人 4 狼）；人数不满足的角色禁用置灰

**4.2 角色库扩展**（基于人数门槛）

| 角色 | 阵营 | 人数门槛 | 能力概要 | 状态 |
|---|---|---|---|---|
| 狼人 | 狼 | ≥6 | 夜晚刀人 | ✅ |
| 村民 | 好 | ≥6 | 无技能 | ✅ |
| 预言家 | 好 | ≥6 | 夜晚验人 | ✅ |
| 女巫 | 好 | ≥6 | 解药/毒药各一 | ✅ |
| 猎人 | 好 | ≥8 | 出局时可开枪带走一人（被毒除外） | ✅ |
| 守卫 | 好 | ≥8 | 每晚守护一人（不能连守） | ✅ |
| 白痴 | 好 | ≥9 | 首次被放逐翻牌免死，此后失去投票权 | ✅ v1.8 |
| 长老 | 好 | ≥10 | 首次被狼刀不死；被毒/被枪/被放逐后好人神职技能失效 | ✅ v1.8 |
| 黑狼王 | 狼 | ≥10 | 出局时可开枪带走一人（被毒除外） | ✅ v1.8 |
| 摄梦人 | 好 | ≥12 | 每晚标记一人，被标者不能被刀 | 未实装 |

- 每个新角色的 AI 决策 prompt、引擎结算逻辑、胜负判定需同步扩展
- **Q4 已关闭**：v1.5 上猎人 + 守卫，v1.8 上白痴 + 长老 + 黑狼王；摄梦人留到后续迭代
- **推荐牌组改为按人数显式配方**（不再「神职不够用平民补」）：9 人起有白痴，10 人起有黑狼王，12 人起有长老。
  早期写法会让 10/12 人局只是「更多平民」，人数上去但信息密度没上去。

**4.3 AI 人格与推理差异化（v1.7）**

- **信息边界**：AI 只知道自己的身份与技能状态；狼人额外知道队友。别人的身份只有被放逐翻牌才公开，
  夜晚死亡不翻牌。AI 视图与观战上帝视角是两个函数，禁止合并。
- **人格参数**：每个角色带 `skill / style / talk / push / suggestibility` 五项 traits，
  外加每局随机的 `mood`；牌感与状态都会抖动，所以同一角色不同局表现不同。
- **差异落到机制而非台词**：记忆窗口（8~24 条发言）、可推理深度、发言字数区间（15~120 字）、
  采样温度（0.6~1.1）都随 traits 变化；不靠一句「你要像新手」。
- **角色池**：12 位 AI，牌感从 0.28（大熊）到 0.85（阿岚），风格覆盖逻辑 / 情绪 / 直觉 / 混沌 / 试探。
- 详见 `docs/AI-PERSONA.md`；断言在 `tests/ai-persona.test.ts`。

### R5 对局生命周期与断线恢复（✅ v1.3 已实现核心）

**状态机**：`创建 → 进行中（night/day/vote 循环）→ 结束（正常结算 / 异常中止）`
- 权威状态在服务端（已实现），客户端只存对局 ID
- **刷新/误关恢复**：对局 ID 存 localStorage，重进首页出现「回到进行中的对局」横幅；一键恢复完整事件流回放
- 服务端房间保留 2 小时；超时自动清理
- 主动退出 = 明确结束（弹确认）；对局结束/中止自动清理本地记录
- **后续（v1.4）**：多端恢复（换设备需登录后从「我的对局」恢复）

## 三、非功能需求

- **性能**：单局 LLM 调用 20~40 次；响应 P95 < 8s（思考型模型）；轮询 1.2s/次
- **安全**：服务端权威状态；观战零信息泄露（已有隐私审计）；开源仓库零密钥
- **成本**：模型可切换（首选 flash 级控制积分消耗）
- **可观测**：对局事件全量留存（events 上限 500 条），便于复盘与排障
